# A/L tournament field

This branch prepares **25 new agents plus 7 references**. It does not start or stop a tournament. Each new agent uses the saved `BASE_P120H50B75_C2` weights with S2, indexed swap-removal and aspiration windows starting at ±500. The tracked default seed adopts those weights and S2; legacy checkpoints that explicitly disable S2 keep that setting. Missing S2 in old JSON still defaults to false.

## The 25 agents

Each `BASE_C2S2_<A>_<L>` checkpoint selects one of each:

- `A0`: no alignment bonus.
- `A40`: original geometric alignment at 40, capped at 200 per side.
- `A80`: original 80/400 alignment.
- `A160`: original alignment at 160, capped at 800.
- `AB80`: 80/400 alignment only with an empty first-leg ray to the enemy royal. This is conservative; it does not enumerate all legal two-leg attacks or recognize capture-through-blocker routes.

The five L settings are mutually exclusive:

- `L0`: off.
- `Lold`: original 4,000-unit last-royal flight term, including its old adjacent-empty-square approximation.
- `Lflight`: only in actual last-royal check, count safe real destinations, including captures, two-square King movement and vacated-square attacks. Stop after two. Retain the existing checked-flight penalty scale. This is a trial, not an established strength gain.
- `Ldefense`: at a checked search frontier with exactly one legal evasion by a non-royal piece, search one extra ply, once per path. This is a royal with no flight of its own and one saving capture/interposition. Reuse the evasion list already generated by normal search. Keep the extension budget in both TT contexts and restore it on return, including timeout. The prototype's defense-count *score penalty* was deliberately replaced by this extension: it allocates effort without taxing a check already resolved by the search or changing exact draw scores.
- `Lmate`: one root-only probe, at most 64 attacking candidates and 256 defense candidates, with a two-millisecond soft deadline inside the normal search budget. Prioritize a fully verified checking move with no evasion, matching its entire route and exempting that proven move from speculative hang-skipping. Normal search assigns its score. Unknown or exhausted probes make no claim and leave normal search ordering intact. Generation is not interruptible; the deadline is soft. The probe does not run at every node or for every root candidate.

These are three new A variants (40, 160, blocker-aware) and three new L variants (verified flights, defense extension, mating probe), in addition to the old and off settings. New modes are serialized checkpoint fields and work in normal builds; `royal-probes` only exposes the measurement harness and legacy smoke overrides.

Swap-removal deliberately changes board traversal order after removal. Aspiration retries double the window, use full windows around mate-range scores, and preserve the last completed iteration on timeout. Both are behavior changes, not fixed-depth equivalence claims. A same-square board move now leaves the square/list indices intact; GameState still handles return-to-origin capture routes itself.

## References and reproducibility

The six retired q-rs winners are `AVG_P120_SEED_C2R`, `C2K100A1D50R`, `T150_P120_T12_C2R`, `C2K50A1`, `SEED`, and `SEEDS2`. They retain their recorded weights and search flags and use the current engine. Their historical registry IDs have a `QRS_` prefix to prevent collisions with mutable names in older grids. The recipe reconstructs them from the pinned August seed and material revisions, including **T150/C50**. Raw checkpoint files are kept out of Git; source hashes and local comparison results are recorded with the private validation artifacts.

The seventh reference is `BASE_P120H50B75_C2`, with A/L/S2 off and engine `LOGIC_PRE_ROYAL_AL` pinned at `68dada78b6dc6a2f867f9df1c567e6102d7201b4`. It uses the actual C2 checkpoint, not that revision's unrelated default seed. The missing pre-L/A snapshot at `b46863a` is also registered and built for the archive; it is not a 33rd entrant. If main advances before merging, update the pre-change logic snapshot to the actual parent of the behavior-changing merge and rebuild it.

Prepare a new output directory locally or after the PR is merged on another machine:

```sh
./deploy/prepare_royal_al_grid.sh models/royal-al-grid
```

This builds binaries, freezes the two historical engines, generates the field and validates all checkpoint policies plus the old-engine pin. Existing outputs are never overwritten. `manifest.json` is written last by the generator; `verified.json` records the validated models and engine hashes. Preparation failures exit nonzero and say that no tournament started. A faster recheck of an already prepared field is:

```sh
python3 deploy/check_royal_al_grid.py --manifest models/royal-al-grid/manifest.json
```

The combined coordinator supports this field by validating and content-pinning each historical engine with its matching `analyze_position` helper. `freeze_history.sh` adds only an explicit transport flag to that revision's existing helper; replay, evaluation, and search remain historical. An unknown/mismatched pair fails before launch. The helper is selected per move's original agent, and its content hash participates in cache identity.

To start the prepared field while continuing a previous run's catalogue:

```sh
python3 deploy/tourney_analysis.py start --run-dir data/raw/tourney/NEW_RUN \
  --manifest models/royal-al-grid/manifest.json --cpus 0,1,2,3 --time-ms 3000 \
  --carry-analysis-from data/raw/tourney/PREVIOUS_RUN
```

Stop the previous supervisor first and back up its saved state. The carry operation uses SQLite backup, preserves completed records and cached searches, exports completed moment JSON, and scans both old and new run state. Old games retain the old saved analyzer/model bindings; new games use the new field's bindings. Resume keeps those sources automatically. CPU handoff is unchanged: three tournament workers plus a fourth shared with analysis, borrowed by the tournament only when analysis is idle. A historical tournament subprocess inherits its worker's CPU affinity.

## Validation commands

```sh
cargo test --locked --all-targets --features royal-probes
cargo test --locked --release --all-targets --features royal-probes
python3 -m unittest discover -s deploy -p 'test_tourney_analysis.py'
cargo build --locked --release --bins --features royal-probes --example royal_probe_smoke
# Run only after all builds and tests finish; one pinned CPU, sequentially.
taskset -c 0 target/release/examples/royal_probe_smoke grid-smoke CORPUS.json > grid-smoke.jsonl
taskset -c 0 target/release/examples/royal_probe_smoke search-new CORPUS.json > search-new.jsonl
```

`grid-smoke` exercises all 25 policies on the first five full-history saved positions with 100 ms budgets, checking move legality and input-state preservation. It is an activation/compatibility check, not a strength trial. `search-new` makes two shuffled three-second runs of off/defense/mate on five saved opening/middle/reversal/late/1,031-ply positions and two forced fixtures. Use the same corpus schema as `benchmarks/royal_eval_smoke/README.md`; raw routes, root scores, nodes, completed depth and probe/extension diagnostics are retained. Builds and timings must not overlap.
