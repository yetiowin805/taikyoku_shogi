# 512v5 sample-mix experiment

Three continuations start from the identical NNUE_W512_v4 checkpoint. Only the
training sampling probabilities differ: v5a uses 90% representative, 8% precursor,
2% mate; v5b uses 85/12/3; v5c uses 95/4/1. These are sampling masses, not quotas
that discard the rest of the corpus. The experiment does not admit agents or
replace tournament models automatically.

## Frozen data and targets

Use all valid saved positions in completed games of the current royal-nnue-v3-32
run at snapshot time. Older historical tournaments are not training sources.
Old feature shards may be reused when the immutable game, baseline, feature
schema, and shard hashes match; their old labels and weights are replaced.
Missing shards are exported with complete game replay. Features are shared by
all three variants, with overflow storage on the VPS root filesystem.

At an analyzed position, use a cached 512v4 label plus the conditional secondary
teacher, if its label is already available. The secondary is the decisive winner
when both sides are optimistic, or when both favor the winner and its estimate
is at least 20% larger; in agreed-advantage draws, use the more conservative
player. Average probabilities with one vote per teacher content identity, using
the deepest completed record for each identity. Without a cached 512v4 label,
retain the saved game evaluation. Do not wait for new analysis. Record coverage,
missing secondary labels, search/model provenance, and diagnostics.

Mate scores are search claims, not proven outcomes. Keep finite precursor targets
finite. Use the same narrowed stratum definition for all three variants: mate claims separated by at most 16 plies form an episode;
non-mate positions 1–23 plies before an episode are precursors. Positions 24 or
more plies before recognition remain ordinary examples. All other
valid positions are representative. The buckets are disjoint. The earlier 128-ply definition was superseded before optimizer training began;
the change reclassifies positions rather than discarding them. The frozen games,
labels, splits, and feature shards remain reusable.

Weight each split by stratum, then related-game group, game, phase/episode, and
position. Long games and repeated episodes cannot gain influence simply by
containing more positions. Within each training cell, boost hard examples using
512v4's probability error `e`: `1 + 3t² - 2t³`, where `t = min(e / 0.35, 1)`.
Renormalize within the cell so difficulty does not change game/stratum mass.
Score these errors once and reuse them in all variants. Do not difficulty-weight
validation or test data.

Keep paired starts and shared 64-ply prefixes in the same split. Inherit the
parent's split assignments, quarantine contradictory inherited groups, exclude
positions seen in the parent's training from holdouts, and deduplicate identical
feature positions across splits. The parent sample index includes inherited
exposure. Report fresh and inherited holdouts separately: inherited validation
is not an independent test of a previously selected parent.

## Training and comparison

All variants use the same seed (20261017), parent, 512-wide architecture, fixed
material baseline, quantization-aware probability objective, probability scale,
and no game-outcome mixture. Draws without classified termination keep their
teacher labels. An epoch is 65,536 weighted draws with replacement, not a complete
pass over every row. Effective batch size is 8, microbatch size 1, up to two CPU
threads. Initial learning rates are 0.0001 for embedding SGD and 0.00015 for
dense Adam (half the previous pilot rates). These are conservative fine-tuning
choices, not measured optima; all three mixtures use the same settings.

Validation and test retain a common 90/8/2 weighting across the three models.
Select checkpoints using the full validation objective; report per-stratum
probability error, source metrics, and fresh/inherited holdout metrics as well.
Evaluate the held-out test split after checkpoint selection. Test results should
not be used for further tuning on this same split.

Use `--epochs 0`: no epoch or wall-clock ceiling. After at least four full windows,
three windows without a cumulative relative 0.5% improvement trigger a
learning-rate halving. Allow two halvings, then stop after another three
unimproved windows. On each reduction, restore the best floating model and its
optimizer state, but halve the **current** rates, without rewinding the sampler
or plateau counters. Every actual validation improvement is eligible for the
best checkpoint, including improvements smaller than the scheduling threshold.
The best checkpoint may remain the parent if continuation does not improve it.

Validate and save an additional checkpoint after 32,768 draws in the first
window. This may become the best model, but does not consume plateau patience.
Save the current and best optimizer/model states together in one atomic training
checkpoint at this boundary and every full window. Resume from the last saved
boundary, including its draw offset and running training loss, so an early
checkpoint neither loses nor duplicates samples. Restore the exported model
manifest from the committed best state after an interrupted publication.
Stable validation plateau is the stopping criterion; no eight-hour watchdog or
mandatory million-draw minimum is used.

The best floating state adds approximately one model's training weights to RAM
and checkpoint storage. `checkpoint_root` in the supervisor config optionally
places resumable states on a separate local filesystem, with a directory per
model; metrics and exported networks remain under the experiment output. Keep
both locations for recovery, and reserve space for atomic checkpoint replacement.

These results compare target prediction, not playing strength. Before promoting
a winner, compare held-out tactical behavior and tournament games under the same
search/time control. One seed per mix is a first comparison, not strong evidence
that small differences are reproducible.

## Supervision and reproduction

`deploy/v5_training.py CONFIG.json` runs snapshot, dense export, difficulty
preparation, then v5a/v5b/v5c sequentially. It pauses only
`taikyoku-dual-labels.service`, obtains the existing analysis lock, and leases up
to two flexible CPUs through the live coordinator. Game workers surrender CPUs
at game boundaries. Tournament and champion workers keep running. The analysis
service is restarted and leases returned on completion/error.

Freeze a code copy and input hashes before launch. Config keys are `repo`, `run`,
`out`, `code`, `python`, `cpus` (the eight physical CPU IDs), `parent`,
`parent_samples`, `base`, `nnue_tool`, `reuse_shards` (a list of shard directories),
`precursor_plies` (23), `extra_shards`, optional `checkpoint_root`, `code_hashes`,
and `input_hashes`. Hash maps are absolute path to SHA-256. `out` and
`extra_shards` must be new experiment directories, separate from live inputs.
The source run remains untouched. Keep the frozen code/config for resumption.

Run under systemd with `LimitNOFILE=65536`, `KillMode=control-group`,
`TimeoutStopSec=infinity`, no
`RuntimeMaxSec`, and `ExecStopPost=/usr/bin/systemctl start
taikyoku-dual-labels.service` for recovery after supervisor failure. Use the
actual mounted training-volume path in `RequiresMountsFor`. The file limit is
needed because the memory-mapped corpus opens one descriptor per feature shard;
the 1,399-game corpus exceeds the default 1,024-descriptor soft limit. Set the
limit on this unit before launch, not on unrelated processes. Inputs and code are
verified before every stage; a failed prerequisite exits nonzero. Restart with
the same config: completed shards, completed difficulty scores, epoch checkpoints,
and completed variants are reused. Never edit the frozen recipe to resume.

Observe `status.json` at the run root, `corpus/report.json`,
`dataset/status.json`, model `metrics.json`, `test.json`, and per-stage logs.
Training does not upload data to a new provider or change live engine manifests.

## Validation before launch

The tiny end-to-end test prepares shared difficulty weights, checks that holdout
rows remain untouched, trains all three mixtures from one parent, and verifies
identical initial validation results. Other tests cover requested mixture mass,
within-stratum proportions, grouped split conflicts, mate/STM signs, immutable
snapshot reuse, conditional cached-teacher identity, unlimited plateau stopping,
and analysis restoration after stage failure. Controlled-curve tests exercise
both LR reductions, exact weights and Adam moments after best-state restoration,
and interruptions at the early and post-reduction checkpoint boundaries.
Existing checkpoint-resume tests
run in the VPS's supported PyTorch environment.
